# 中转站侧接入契约

本文件写给**服务端**（你的中转站）实现者。客户端（本仓库）只做一件事：
接收 `web_prompt` 任务 → 用**用户自己电脑上的浏览器**跑完 → 回传一个 OpenAI 格式的响应。

## 1. 为什么不能当成普通 HTTP 上游

普通上游是「服务端 `fetch(baseUrl)`」。但这里浏览器在**用户家里的 NAT 后面**，
服务端连不进去。所以必须复用**设备投递**（连接器长轮询）：服务端把任务塞进该设备的队列，
等用户的连接器取走并回报结果。

> 顺带一提：本仓库早先做过一版「服务端固定 HTTP 上游」的适配器（把服务器本机的
> 浏览器桥接包成 `http://127.0.0.1:8791/v1`）。那套只适合**单机共享**场景，
> 也就是「共享你服务器那台浏览器」，与本仓库的「用调用者自己的浏览器」是两件事。
> 建议把它们分成两个模型（见第 4 节）。

## 2. 任务契约（服务端 → 客户端）

投递到该用户**默认网页桥接设备**的队列，任务名固定 `web_prompt`：

```json
{
  "name": "web_prompt",
  "args": {
    "body": {                      // 原始 OpenAI 请求体，原样透传即可
      "model": "web-deepseek",
      "messages": [ { "role": "user", "content": "你好" } ],
      "tools": [ /* 可选，会透传给网页端做参数校验 */ ]
    },
    "timeoutMs": 240000            // 可选：本机等网页的预算，缺省 240s
  }
}
```

要点：

- **`body` 原样透传**。不要试图在服务端拼提示词——把消息编成网页端能懂的协议、
  以及校验网页回复里的 `request_id`/`kind`/工具参数，都由客户端用上游那份
  `protocol.js` 完成（`prepareRequest` / `parseReply`），服务端重复实现只会造成协议漂移。
- **不要投递 `stream: true` 期望逐字流**：设备投递是请求/响应，没有 token 级流。
  客户端会返回一个完整的（非流式）响应；若调用方要 SSE，由服务端自行拆成
  「一个 content 分片 + 结束分片」的 SSE 即可（与本仓库 `web-bridge-openai.js` 里的做法一致）。

## 3. 结果契约（客户端 → 服务端）

客户端通过连接器的结果回报接口提交：

```json
{
  "jobId": "job_xxx",
  "ok": true,
  "output": "{\"id\":\"chatcmpl-...\",\"object\":\"chat.completion\",\"choices\":[...]}",
  "error": "",
  "meta": { "agent": "0.1.0", "kind": "final", "elapsedMs": 9317 }
}
```

- `output` 是**一个 OpenAI 格式的完整响应**（`choices[0].message.content`，或工具调用时的
  `tool_calls` + `finish_reason: "tool_calls"`）。服务端可直接原样回给调用方，**无需转换**。
- **没有 `usage`**：网页端不提供真实用量，客户端也拒绝伪造。请把 token/花费按 0 记账，
  不要为了报表好看去估算。
- `ok: false` 时看 `error`（已裁剪到 900 字符以内），常见值：
  - `Chrome/Edge 扩展未连接…`
  - `本机桥接服务未在 127.0.0.1:3081 响应…`
  - `网页回复的请求 ID 不匹配，已拒收。`（协议校验失败，属正常防御）

## 4. 模型与设备路由建议

| 模型名 | 含义 | 路由方式 |
|---|---|---|
| `web-deepseek` | **调用者自己的浏览器** | 按调用者 owner → 默认网页桥接设备 → `web_prompt` 投递 |
| `web-deepseek-shared` | 服务器本机浏览器（共享，可选） | 普通 HTTP 上游，指向服务器上的本机适配器（如 `http://127.0.0.1:8791/v1`） |

⚠️ **模型命名有一个坑**：如果你已经存在 `api.deepseek.com` 的上游且
`matches: ["deepseek"]`，那么 `deepseek-web` / `deepseek-flash` 之类**以 `deepseek` 开头**的模型名
会被它按前缀优先命中（路由通常是「前缀优先 + 按 id 升序」），永远轮不到桥接。
所以桥接用的模型名请**不要**以 `deepseek` 开头（本仓库客户端默认用 `web-deepseek`）。

**设备选择**：一个账号可能配对多台电脑。建议在控制台提供「网页桥接默认设备」设置：

- 已设置 → 投给那台；它离线或不存在 → 返回 503，并提示用户去控制台确认设备在线。
- 未设置 → 可在该账号的设备里自动选「最近心跳且上报了网页桥接能力」的一台。

> 能力识别：本仓库客户端配对时上报 `name = "<主机名> · 网页桥接"`、`platform = "<os>-<arch>"`、
> `version = 0.1.0`。若你的设备表有 capability 字段，建议直接加一个 `web_prompt` 能力位，
> 比按名字猜更可靠。

**投递超时必须放大**：连接器通道的默认单次调用超时通常是 180s，而网页一轮最长按 240s 预算，
所以投递时要显式给到 **300s**：

```
dispatch(deviceId, { name: 'web_prompt', args: { body } }, { timeoutMs: 300_000 })
```

超时分层（必须逐层变大）：

```
本机等网页 240s  <  broker 自身任务计时 260s  <  服务端投递预算 300s  <  调用方客户端超时
```

## 5. 鉴权与归属

- 设备归属由**配对流程**决定：控制台生成配对码 → 客户端 `pair` → 服务端签发该设备令牌，
  并把它绑定到生成配对码的那个 owner。投递时必须**只**投给该 owner 的设备（防越权）。
- 连接器只处理 `web_prompt`；投递别的工具它会明确报错（不会静默吞掉任务）。
- 建议给这个模型单独限速：消耗的是用户自己的网页额度，滥用会把它刷爆。

## 6. 托管一键安装器（可选，但强烈建议）

把客户端分发给使用者最省事的方式，是让**中转站自己**托管安装脚本与安装包，使用者只需一行命令
（形态与你现有的连接器安装完全一致）。

放置两个文件到 `public/agent/`：

| 文件 | 说明 |
|---|---|
| `webbridge.ps1` | 一键安装器（磁盘上带 UTF-8 BOM 供 `-File` 执行；对外提供时**必须去掉 BOM**，否则 `irm \| iex` 报错） |
| `webbridge.zip` | 安装包 = 客户端源码 **+ `node_modules`（ajv 及其依赖，约 1.3MB）**，这样使用者**不需要 npm install** |

再挂三个路由：

```js
app.get('/agent/runner/webbridge.ps1', (req, res) => sendRunnerScript(req, res, 'webbridge.ps1'));
app.get('/agent/runner/webbridge.md', ...);        // 给 AI 读的安装协议（去 BOM 后按 text/markdown 返回）
app.get('/agent/runner/webbridge-package', ...);   // 见下面的注意事项
```

`webbridge.ps1` 里的 `__SERVER__` 会被替换成请求来源的站点地址（与 `install.ps1` 同一机制），
所以每个中转站托管自己的副本即可，使用者不需要手填地址。

### ⚠️ 两个实测踩过的坑

1. **安装包路由的路径不要以 `.zip` 结尾**。本站在攻击特征里有
   `\.(sql|bak|old|zip|tar|tgz|rar|7z)$`，任何 `.zip` 下载请求都会被判成「扫描敏感文件」并 **403**
   （实测被自家 WAF 拦下，还记了一条 critical 安全事件）。所以路由用 `webbridge-package`，
   下载文件名交给 `Content-Disposition` 决定，使用者拿到的仍然是 `dsh-webtokens-lite.zip`。
2. **`irm | iex` 的脚本不要 `exit`**。在交互式 `iex` 场景下 `exit` 会直接关掉使用者的 PowerShell 窗口
   （AI 代跑时会掐断它自己的 shell）。失败用 `throw`、`-Doctor` 自检用 `return`；
   用 `powershell -File` 执行时未捕获的 `throw` 同样让进程以退出码 1 结束。

## 7. 隐私（请如实告知你的用户）

- 内容会出现在**调用者自己的** DeepSeek 网页会话里（这是网页版本质）。
- 内容仍会**经过中转站服务进程**（要转发/路由/记账）。若服务端不落库正文，
  请在文档里写清楚；若落库，务必让用户知情。
- 内容会发往 DeepSeek 服务器。提醒用户不要在不宜外发的项目里使用。
